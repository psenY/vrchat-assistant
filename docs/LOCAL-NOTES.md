# 本部署（fork）有意与上游不同之处

> 面向本部署的维护者与 agent。**这些差异是刻意保留的**，不要为了「与上游一致」而在不知情的情况下改回去；
> 每一条都写明依据与覆盖方式。其余差异一律走上游 PR（见仓库 PR 列表）。
> 最后更新：2026-10-16。

## 1. WS 应用层静默重连默认值：本部署 3 小时（上游 60 分钟）

- 位置：`core/ws-manager.js` 的 `SILENT_RECONNECT_DEFAULT_MS`。
- 依据：本部署（24 好友规模）**实测合法静默最长 157.8 分钟**（另有一档 27 分钟级）；上游通用默认 60 分钟是按「数百好友」的实测尾部（约 27.4 分钟）定的 ⇒ 按上游默认会在本部署的安静时段误重连。
- 覆盖方式：`VRC_MONITOR_WS_SILENT_RECONNECT_MS` 环境变量（上游已支持该开关，本部署只改默认值）。
- 处置：**不提上游**（属部署取舍，不是上游缺陷）。

## 2. `tracked_non_friends` 表有三个「只有列、没有写入者」的字段

- 字段：`last_activity` / `platform` / `world_id`。
- 现状：`core/init-db.sql` 里建了列，但**全仓库没有任何代码写入它们**（追踪页的信息来自 `friends`/事件表）⇒ 一直为空。
- 处置：**不提上游**（属历史残留）。将来清理时需按 DEVELOPMENT.md §2-4 走幂等迁移，并同步本章。

## 3. ❌ 曾有意保留、现已确认应当取上游的一条（留档以免再犯）

- `ui/src/style.css` 里 `@media` 内的 `.header-right .p-button:has(.pi-users) { display: inline-flex; }`：**上游评审已删**（理由：没有任何规则隐藏过该按钮 ⇒ 是死规则）。
- 本部署一度保留（属误留）⇒ **正确做法是取上游**，本部署也应删（已列入本地清理项，未随任何 PR 提交）。
